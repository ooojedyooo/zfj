## 0. 文档契约

### 0.1 来源标记（沿用 `skin-system.md` §0.1 全项目规矩）

| 标记 | 含义 | 本文档中的用法 |
|---|---|---|
| **推导** | 从听感目标 / 人耳特性 / 平台物理推得 | 绝大多数频率、时长、包络形状 |
| **算得** | 由其他参数确定性计算得到 | 音名频率（A4=440 十二平均律）、分频比、dB↔线性换算 |
| **量测** | 真机 / 工具实测 | 仅引用工程已知结论（如包体 449K、上限 4MB、`turnSeconds<=5`） |
| **暂定，真机听感验证** | 无来历可依，需真机调 | 增益绝对值、混音 duck 量、氛围音量、听感形容词的最终落点 |

**铁律**：不写无来历的 magic number；「代价」只在存在互斥选项处写；不写「待某某确认」的无主悬挂项——
要么给出裁决和出处，要么明确写「暂定，真机听感验证」。

### 0.2 一句话结论

16 个音效事件，共享一套振荡器 + 噪声合成器；皮肤只切 3 个参数；做极简氛围（非旋律），
默认开、随首个手势解锁；T-08 靠「结果音只认我自己那一炮的服务端结果」实现，音频层不接触对方棋盘。

## 1. 系统总览（工程实现的骨架）

### 1.1 音频图

```
[各事件声部: OscillatorNode / AudioBufferSourceNode → 各自 GainNode(包络) → 各自 BiquadFilterNode]
        │
        ├─→ bus.sfx (GainNode, gain=1.0 算得:中性单位) ─┐
        └─→ bus.amb (GainNode, gain=0.03 推导:-30dB) ──┤
                                                        ├→ MASTER (GainNode, 0.8 推导:留 20% 余量)
                                                        ├→ MASTER_LP (lowpass 7000Hz 推导:见 §7.1)
                                                        └→ LIMITER (DynamicsCompressor 推导:见 §4.3)
                                                                          └→ destination
```

- **噪声缓冲**：运行时生成 1 份 0.5 秒 mono 白噪 `AudioBuffer`，长度 `0.5×44100×4 ≈ 88 KB`（算得），
  所有噪声层共用它、每次从随机 offset 起播（推导：制造变体而不增加资源）。**仍然零音频文件**。
- **包络写法**：`setValueAtTime(peak, t)` → `exponentialRampToValueAtTime(0.0001, t+dur)`。
  不可 ramp 到 0（Web Audio 抛错）；0.0001 比 -80 dB 还低（算得），听感等同静音。
- **Oscillator 不池化**：一次一建、`stop()` 后由引擎回收（推导：one-shot 是 Web Audio 的设计用法）。
  若真机 profiling 发现 GC 抖动，再考虑池化——暂定，真机验证。

### 1.2 生命周期与解锁

- `AudioContext` **延迟到首个用户手势才创建 / resume**（微信小游戏音频必须手势后启动；`skin.js` 已用 `wx.getStorageSync` 范式，静音键沿用）。
- 首个手势（大厅任意点击）同时做两件事：`ctx.resume()` + 播 `sfx.ui.tap`——
  这声 tap 本身就是「声音已开」的听觉确认，不需要额外提示文案（推导）。
- 切后台 `visibilitychange:hidden` → `ctx.suspend()`；回前台若未静音则 `resume()`（推导：省电、避免后台出声）。
  工程已有后台 60s 回来 dt 跳变的处理（`core/fx.js`），此钩子与之同源。

### 1.4 事件驱动接线铁律（与 rAF 渲染解耦）⭐ 工程必读

> **音效是「某一刻发生了一件事」的离散响应，不是画面状态的函数。**
> 任何音效调用都不得出现在 `render()` / `draw()` / 每帧循环里——那会在 60 fps 下把一声 tap 变成每秒 60 声。
> 判据：**若某音效的触发条件在连续两帧都为真，它就必须改挂到状态跃变点或回调上。**

| 事件 | 唯一合法触发时刻（离散） | 禁止的接线位置 |
|---|---|---|
| `sfx.fire` | **点击开火那一刻**，`battle.js:808` 发出 `api.fire` **之前**，响一次 | 结果回调里；`render` 里 |
| `sfx.miss` / `sfx.hit` / `sfx.kill` | **`battle.js:808` 返回 `res.result` 之后**、`812` 弹 feedback 前后，按三态**三选一**响一次（_RESULT 常量在 19–22 行） | 点下时提前响；与 `sfx.fire` 合成一个音；`render` 里 |
| `sfx.tick` / `sfx.tick.urgent` | **`update:145` 的秒变化点**（250 ms 累加器防抖），剩余 5/4/3/2/1 **各一记**离散音 | `render:575` 的 `urgent` 布尔（每帧为真）——**严禁**；持续音 / loop |
| `sfx.skin` | `lobby.js:352` 调用 `theme.applySkin` 成功之后，响一次 | `render` 里读 `colorVersion` 变化再播（每帧读到同一版本就重播） |
| `sfx.deploy.*` | `deploy.js` 的 touch/pointer 回调里，动作成立那一刻 | `render` 里读 `this.drag` 状态 |
| `sfx.round.start` | `myTurn` 由 false→true 的**跃变点** | `render` 里读 `myTurn` 为真 |
| `sfx.win` / `sfx.lose` | `finished` 首次为真的跃变点（配合已有 `resultHandled` 去重） | `render` 里每帧读 `finished` |

**通用实现约束**（推导）：
- 每个事件暴露 `play(eventId)` 一次性函数；调用方只在回调 / 状态跃变处调用，不在绘制路径调用。
- 需要「状态变了才响」的（`round.start`/`win`/`lose`/`skin`），调用方维护 `prev` 值比较，或复用已有去重标志（`battle.js` 已有 `resultHandled`）。
- `amb.*` 是唯一允许「持续运行」的声部，但它的启停也只发生在解锁 / 静音 / 场景切换的离散时刻，与帧无关。

**可行性锚点（量测，程基岩 T17）**：`wx.createWebAudioContext()` 自基础库 **2.19.0+** 支持，项目基础库 **3.5.5**；
`OscillatorNode` / `GainNode` / `BiquadFilterNode` / `createBuffer` / `BufferSource` 全部可用——**方案 A 零音频文件成立**。

## 2. 音效事件表（触发 + 合成配方）

每个事件给出：**触发时机**（尽量锚到代码）、**听感目标**（具象形容词 + 比喻）、**合成配方**（波形 / 频率走向 / ADSR / 滤波 / 叠层）。
ADSR 单位 ms；`A`=attack，`D`=decay（到 0.0001 的时长），无 sustain 的 one-shot 不列 S/R。
增益为相对 `bus.sfx` 的峰值系数（0~1），括号内为 dB（算得：20·log10(g)）。

---

### 2.1 `sfx.ui.tap`
- **触发**：大厅 / 房间 / 设置 / 任意按钮与 Tab 的 tap（通用导航）；离散回调，见 §1.4。
- **听感**：指尖敲玻璃珠——干、短、亮点一闪即收；像鼠标微动开关的「嗒」。
- **配方**（单声部）：`triangle`（皮肤可变，§3）· f: 880→587 Hz over 30 ms（算得：880/1.5=587 = 纯五度下坠，读作「确认」而非警报）· A=4, D=38（推导：总长 <50 ms 才读作「即时」，低于 ~100 ms 的同时性阈；A 从 2 提到 4 是为了不被去重截掉起始瞬态，见下）· lowpass 4000 Hz 恒定（推导：砍掉数码毛刺）。
- **增益**：0.30（−10.5 dB，暂定，真机听感验证）。
- **皮肤**：波形 + 尾长跟随；频率 / 滤波 / 增益恒定。
- **去鲁棒性**（工程 T17 要求）：tap 音与开火音在同一次点击撞车时，工程做 **60 ms 跨事件去重**；
  本音的识别特征放在 10–30 ms 的主体上，**不依赖 0–2 ms 的初始瞬态**——即使被截掉开头几毫秒仍读作「嗒」。

### 2.2 `sfx.skin`
- **触发**：`lobby.js:352` 调用 `theme.applySkin` 成功之后（原地换色并递增 `colorVersion` 的那一次），响一次；
  音频读 `theme.skin`（`abyss` / `dusk`）选音色。禁止在 render 里轮询 `colorVersion` 再播（§1.4）。
- **听感**：水面泛起的两点微光，先低后高，像设置被「点亮」。
- **配方**（两层顺序）：
  - n1 @ t=0：`sine` 523 Hz (C5)，A=4, D=90。
  - n2 @ t=70 ms：`sine` 784 Hz (G5 = C5×1.5，纯五度，算得)，A=4, D=90。
  - lowpass 5000 Hz 恒定（推导：亮度够但不刺）。
- **增益**：0.40（−8.0 dB，暂定）。总时长 ~160 ms。
- **皮肤**：尾长跟随（dusk 余韵略长）；音高 / 音程恒定——五度关系是「切换成功」的语义，跨皮肤必须一致。

### 2.3 `sfx.room.enter`
- **触发**：进入房间 / 匹配成功的大厅→房间转场。
- **听感**：一扇轻门被推开，两音柔和铺开，像门铃的软起音。
- **配方**（两层同时，柔和起音区别于 `sfx.skin` 的断点）：
  - `sine` 392 Hz (G4) + `sine` 523 Hz (C5，纯四度，算得)。
  - A=25（推导：慢起音 = 不惊扰），D=190；lowpass 3500 Hz。
- **增益**：0.35（−9.1 dB，暂定）。总时长 ~215 ms。
- **皮肤**：波形 + 尾长跟随；滤波恒定。

### 2.4 `sfx.deploy.place`
- **触发**：飞机拖到合法格、松手吸附落位。
- **听感**：棋子稳稳落在木盘上的「咔哒」——有重量、有接触面。
- **配方**（两层叠）：
  - 主体：`triangle`（皮肤可变）· 300→180 Hz over 90 ms（推导：约 1.67:1 下坠给「重量感」）· A=1, D=110。
  - 接触点：白噪 12 ms → bandpass 2500 Hz（Q≈1，推导：塑料 / 金属接触的脆点，bandpass 防嘶）· 增益为本体 0.25。
  - lowpass 3500 Hz。
- **增益**：0.50（−6.0 dB，暂定）。
- **皮肤**：波形 + 截止 + 尾长全跟随（dusk 的木质余韵在此最明显）。

### 2.5 `sfx.deploy.rotate`
- **触发**：布阵期旋转飞机 90°。
- **听感**：轻机械棘轮的「嗒」，音高略上扬像转到位。
- **配方**（两层叠）：
  - `triangle`（皮肤可变）· 520→640 Hz over 45 ms（推导：上行小二度多 = 动作完成）· A=1, D=55。
  - 白噪 8 ms → highpass 1500 Hz（推导：只留棘轮的「齿感」）· 增益为本体 0.20。
  - lowpass 4000 Hz。
- **增益**：0.35（−9.1 dB，暂定）。
- **皮肤**：波形 + 尾长跟随；频率 / 滤波恒定。

### 2.6 `sfx.deploy.invalid`
- **触发**：松手落在非法格 / 重叠 / 出界，未吸附。
- **听感**：闷闷的、软的「不行」——像隔着棉布敲门，绝不刺耳。
- **配方**（单/双层）：
  - `square`（恒定，**不随皮肤变**，见下）· 160→140 Hz over 140 ms（推导：低频下坠 = 否定；<1 kHz 避免烦人）· A=8（推导：慢起音软化方波的硬）· lowpass 900 Hz（推导：闷住方波谐波）。
  - 可选第二 `square` 150 Hz 轻微失谐制造缓慢拍频（暂定，真机听感验证）。
- **增益**：0.40（−8.0 dB，暂定）。
- **皮肤**：全恒定。理由：错误反馈必须跨皮肤保持同一「否定」语义，不能被 dusk 的明亮尾音软化成「好像可以」。

### 2.7 `sfx.deploy`（确认布阵 / 进入战斗）
- **触发**：点击「开战 / 确认布阵」，布阵→战斗转场。
- **听感**：短促的三音整队号，像舰载机弹射前的「就绪」确认。
- **配方**（三层顺序，major 三和弦分解）：
  - n1 @0：392 Hz (G4) · n2 @90：523 Hz (C5) · n3 @180：659 Hz (E5)；均 `triangle`（皮肤可变）。
  - 每音 A=5, D=150；lowpass 5000 Hz。
- **增益**：0.70（−3.1 dB，暂定）。总时长 ~330 ms。
- **皮肤**：波形 + 尾长跟随；音高 / 和弦恒定。

### 2.8 `sfx.round.start`
- **触发**：轮到我方回合开始（与 `sfx.round.start` 语义绑定 `myTurn` 由假变真）。
- **听感**：温厚的中音「该你了」，像掌心被轻拍一下——比 `sfx.skin` 更饱满、更慢起。
- **配方**（两层同时）：
  - `triangle` 659 Hz (E5) + 低八度 `sine` 330 Hz（算得：659/2）作厚度。
  - A=15（推导：慢起音 = 提醒而非惊吓），D=220；lowpass 4500 Hz。
- **增益**：0.50（−6.0 dB，暂定）。
- **皮肤**：波形 + 尾长跟随；音高 / 滤波恒定。

### 2.9 `sfx.fire`
- **触发**：我方点击开火那一刻——`battle.js:808` 发出 `api.fire` **之前**响一次；结果音另起，不合并（§1.4）。
- **听感**： compact 炮——低频后坐顶住手心， followed by 短促「咻」的炮口气流；像拍一只皮球而不是放鞭炮。
- **配方**（两层叠）：
  - 后坐：`triangle`（皮肤可变）· 240→60 Hz over 150 ms（推导：4:1 大跨度下坠 = 发射；收在 60 Hz 主要靠体感，手机扬声器放不出但给了厚度）· A=1, D=160。
  - 炮口：白噪 90 ms → lowpass 从 4000→600 Hz 扫频（推导：气流由亮转暗 = 炮口余烟）· 增益为本体 0.35。
- **增益**：0.60（−4.4 dB，暂定）。
- **皮肤**：波形 + 截止 + 尾长跟随（sweep 终点按 `LP_SCALE` 缩放，起点仍受 MASTER_LP 约束）。

### 2.10 `sfx.miss`
- **触发**：结果三态之一——`battle.js:808` 返回 `res.result` 后判定为 `miss` 时响一次（`resultOf(k) === 'miss'`，_RESULT 常量 19–22 行）；在点下时绝不提前响（§1.4）。
- **听感**：石头落进沙里「噗嘶」一声散掉，低而钝，**没有金属余响**。情绪：轻微失落，不惩罚。
- **配方**（两层，全噪声主导）：
  - 气声：白噪 220 ms → bandpass 1200→400 Hz 下扫（推导：能量耗散 = 打空）· 主声部。
  - 低频体：`sine` 300→200 Hz over 120 ms · 增益为噪声 0.30（给一点落点，不至于只剩沙沙声）。
  - lowpass 2500 Hz。
- **增益**：0.45（−6.9 dB，暂定）。
- **皮肤**：仅尾长 + 截止跟随；**全噪声主导这一性质恒定**——绝不能被做成听起来像 `sfx.hit`。

### 2.11 `sfx.hit`
- **触发**：结果三态之一——`battle.js:808` 返回 `res.result === 'hit'` 后响一次（机翼 / 机身 / 机尾，非机头）；三态三选一（§1.4）。
- **听感**：金属装甲被敲中的「叮」——亮、脆、短，带一点非谐音的金属味；像扳手敲钢管。
- **配方**（三层叠）：
  - 基音：`triangle` 900→520 Hz over 130 ms（推导：清脆下坠 = 命中确认）。
  - 非谐泛音：`triangle` 1340 Hz 恒定（算得：1340/900≈1.49，非整数比 → 钟/金属感而非乐音）· 增益为基音 0.5。
  - 撞击点：白噪 25 ms → highpass 2000 Hz · 增益为基音 0.2。
  - lowpass 4500 Hz（皮肤缩放后 dusk 可能到 5175，仍被 MASTER_LP 7000 兜住）。
- **增益**：0.65（−3.7 dB，暂定）。
- **优先级**：P1，低于 `sfx.kill`（§4.2）。
- **皮肤**：波形 + 截止 + 尾长跟随；两个频率比 1.49 恒定（金属感是语义）。

### 2.12 `sfx.kill`
- **触发**：结果三态之一——`battle.js:808` 返回 `res.result === 'kill'` 后响一次（打中机头，整机击毁）；战报标记「击毁」。
- **听感**：两段式——先金属被撕开的「哐」，紧接低沉的爆裂与散落；像易拉罐被踩扁后滚落。全曲最响、最有终局感。
- **配方**（三段，分时使用）：
  - 阶段 1 @0（撞击）：`sawtooth`（皮肤可变）· 720→180 Hz over 220 ms + 白噪 60 ms → highpass 1500 Hz（撕裂点）· A=1。
  - 阶段 2 @90 ms（爆裂）：`triangle` 140→45 Hz over 350 ms + 白噪 300 ms → lowpass 1200→200 Hz 下扫（碎片散落）。
  - 阶段 3 @180 ms（坠落）：`sine` 600→200 Hz over 300 ms · 增益为阶段 1 的 0.25（暂定，真机听感验证；忙时可砍）。
  - 各段 lowpass 按皮肤 `LP_SCALE` 缩放。
- **增益**：0.90（−0.9 dB，暂定）——全表最响，但被 master 0.8 + limiter 兜住（§4.3）。
- **优先级**：P0 最高：抢占所有低优先级声部；duck 氛围（§4.2 / §5.4）。
- **皮肤**：波形 + 截止 + 尾长跟随；三段时序（0/90/180 ms）恒定。

### 2.13 `sfx.tick`
- **触发**：我方回合倒计时在 `update:145` 的秒变化点（250 ms 累加器防抖），剩余 > 5 s 时那一记离散音；
  紧急阈值 5 s 为量测自代码。**不是 `render:575` 的 urgent 布尔**——那是每帧求值的视觉状态，音频挂上去会每帧重触发（§1.4）。
- **听感**：极轻的秒针「嗒」，像桌上的石英钟——存在但不催。
- **配方**：`sine` 1000 Hz over 25 ms（推导：中高频靠短时长避免刺耳）· A=1, D=25 · lowpass 3000 Hz。
- **增益**：0.22（−13.2 dB，暂定）——秒音是最容易烦人的，必须最轻。
- **皮肤**：全恒定。理由：时间提示是系统语义，跨皮肤必须一模一样。
- **仅在本人回合响**：对方回合不响（推导：那时候玩家无事可做，秒音只剩噪音）。

### 2.14 `sfx.tick.urgent`
- **触发**：我方回合剩余 ≤ 5 s，在 `update:145` 的秒变化点各响一记——即 **5、4、3、2、1 共五记离散音**，
  不是持续 beacon，也不是 loop；挂到 `render:575` 会每帧重触发（§1.4）。
- **听感**：双声「哔—哔」beacon，比普通 tick 高、锐、响一档；像微波炉结束前的提示。
- **配方**：两枚短音 @t=0、@t=110 ms：`triangle` 1500 Hz 与 1650 Hz（推导：两音略不同 → 区分于单声 tick；小三度内不刺）· 各 A=1, D=45 · lowpass 4500 Hz（再被 MASTER_LP 7000 兜）· lowpass 恒定不随皮肤。
- **增益**：0.50（−6.0 dB，暂定）。1500 Hz 落在人耳敏感区，故靠「短（45 ms）+ 增益封顶 0.5 + 主低通」三重约束防刺（推导）。
- **皮肤**：全恒定（同 `sfx.tick`，系统语义）。

### 2.15 `sfx.win`
- **触发**：结算态判定胜利（`battle.js` `finished` + 胜方为我）。
- **听感**：明亮的大三和弦分解上行，最后的和弦稳稳落住；像晨光铺开，释然而不喧闹。
- **配方**（四音分解 + 低根）：
  - 523 (C5) @0 · 659 (E5) @110 · 784 (G5) @220 · 1047 (C6) @330；均 `triangle`（皮肤可变）。
  - 每音 A=5, D=300；末音 D=600（推导：终止感需要更长余韵）。
  - 低根 `sine` 262 Hz (C4) @330, A=20, D=550（算得：1047/4≈262，给和弦重量）。
  - lowpass 6000 Hz（皮肤缩放）。
- **增益**：0.85（−1.4 dB，暂定）。总时长 ~930 ms。
- **优先级**：P0，duck 氛围。

### 2.16 `sfx.lose`
- **触发**：结算态判定失败。
- **听感**：下行小调三音，轻、慢、带一点没说完的余味；像日落时的钟声，不刺耳不羞辱。
- **配方**（三音下行 + 低根）：
  - 440 (A4) @0 · 370 (F#4) @160 · 294 (D4) @320；`sine`/`triangle`（皮肤可变）。
  - 每音 A=12（推导：慢起音 = 柔和），D=350；lowpass 3500 Hz（比 win 暗，情绪自然下沉）。
  - 低根 `sine` 147 Hz (D3) @480, A=25, D=450（算得：294/2）。
- **增益**：0.70（−3.1 dB，暂定）——刻意比 `sfx.win` 轻，不把失败「盖章」。总时长 ~930 ms。
- **优先级**：P0，duck 氛围。

## 3. 皮肤音色差异（3 参数切换，共用一套合成器）

### 3.1 裁决：只切 3 个参数

| 参数常量名 | 含义 | `abyss` 深海指挥室 | `dusk` 暖砂沙盘 |
|---|---|---|---|
| `WAVE` | 主体振荡器波形（字符串枚举） | `'sine'`（纯、冷、声呐般） | `'triangle'`（含更多低中次谐波，暖、有木质体感） |
| `LP_SCALE` | 各事件基础 lowpass 截止的倍率 | `0.75`（更暗，像在水下；推导） | `1.15`（更开、更亮；仍被 MASTER_LP 7000 兜住；推导） |
| `TAIL_SCALE` | 各事件 decay / release 时长的倍率 | `0.70`（更干、更短促，仪表盘质感；推导） | `1.30`（余韵更长 = 沙盘的柔和空间感；推导） |

- 三值全部为「推导：从两套皮肤的视觉情绪（冷蓝电子 / 暖褐沙盘）反推听感」；**具体数值暂定，真机听感验证**。
- `LP_SCALE` 只缩放各事件已写的 lowpass 截止；`MASTER_LP = 7000 Hz` 是硬上限，不受皮肤影响（§7.1）。
- 代码结构建议（推导，非硬约束）：`WAVE` 用查表选择 oscillator `type`；`LP_SCALE`/`TAIL_SCALE` 作为乘法系数在 voice 构造处一次性应用，不要在每个事件里写两遍。

### 3.2 什么随皮肤变 / 什么恒定

| 随皮肤变（3 项） | 恒定（跨皮肤必须一致） |
|---|---|
| 主体振荡器波形 `WAVE` | 事件 ID 与触发时机 |
| lowpass 截止倍率 `LP_SCALE` | 所有基频与频率走向（音高是语义：miss/hit/kill 不能换皮就变） |
| 尾长倍率 `TAIL_SCALE` | 各事件的包络**形状**（ADSR 比例），只有绝对时长被 `TAIL_SCALE` 缩放 |
| — | 相对音量层级 / 优先级 / duck 规则 / 总音量上限 |
| — | 静音与解锁行为 |
| — | 主低通 / limiter / 同发数上限 / T-08 约束 |

**明确的例外**（恒定，不随皮肤）：`sfx.deploy.invalid`、`sfx.tick`、`sfx.tick.urgent`——
三者都是系统语义反馈，跨皮肤变化会损害可学习性（§2.6 / §2.13 / §2.14 已各自说明理由）。

### 4.2 优先级与同时触发避让

- **P0**（kill / win / lose）：抢占——触发时对正在响的 P1/P2/P3 声部做 30 ms 淡出并 `stop()`。
- **P1**（hit / miss / fire）：彼此可共存，受同发数上限约束；超载时先停最老的 P1。
- **P2**（deploy* / skin / room.enter / round.start）：受同发数上限；超载先停。
- **P3**（tick / tick.urgent / ui.tap）：**永不抢占**，若已达上限直接丢弃——宁可少一声滴答，不要糊成一团（推导）。
- **「击毁盖过命中」**：同一炮口只产生一个结果（服务端结果唯一），工程需按 shot key 去重；
  若因轮询重复推送导致 `hit` 与 `kill` 在 100 ms 内都到达，只播 `kill`，丢弃 `hit`（推导：防连播穿帮）。
- **氛围 duck**：P0 触发时 `bus.amb` 在 60 ms 内降到 `0.012`（−38 dB，算得：0.03×0.4），
  保持 500 ms，再用 800 ms 升回 0.03（推导：−8 dB 足够「退到后面」又不会形成明显的泵感抽空）。

### 4.3 总音量上限（防叠加爆音）

- `MASTER_GAIN = 0.8`（推导：给 limiter 与同时发声留 20% 余量）。
- `LIMITER`: `threshold = -6 dB`, `knee = 0 dB`, `ratio = 20:1`, `attack = 0.003 s`, `release = 0.15 s`
  （推导：接近 brickwall 的压缩器；3 ms attack 抓住瞬态，150 ms release 避免抽吸）。
- `BUS_SFX_GAIN = 1.0`（算得：中性单位，层级由各事件系数承担）。
- **同发数上限 `VOICES_MAX = 6`**（推导：即使全部取最大系数 0.9，6 声叠加峰值约 5.4，
  经 master 0.8 → 4.3，被 limiter 压在 −6 dB 阈值附近；再多糖度与响度都不划算）。

## 5. 氛围 BGM

### 5.1 裁决：做「极简氛围」，不做旋律；默认开，可一键关

用户已批准方案 A（零资源、纯振荡器合成）。方案 A 能做氛围 / 节奏、**做不了完整旋律**——
所以这里不是「要不要 BGM」的审美选择，而是「在能力上限内做哪一种」的工程选择。下面把「不做」与「做」两条路摊开，不是硬凑。

| | **不做氛围（纯静音底）** | **做极简氛围（本规格裁决）** |
|---|---|---|
| 能拿到什么 | 彻底零音频常驻、零耗电、零疲劳风险；实现最简单 | 填住「对方回合」约 20 s 的死寂；给两套皮肤一个额外的情绪层 |
| 付出什么 | 战斗中最长的 20 s 空窗完全无声，回合制游戏会显得「卡住 / 掉线」；玩家更依赖震动与视觉，而本项目无震动（量测：代码中无 `wx.vibrate`） | 纯振荡器 pad 无旋律推进，长时间可能变「背景嗡嗡」引起疲劳；常驻节点有微小耗电 |
| 代价是否可逆 | 加回来要新写一段合成器与总线 | **只需翻一个布尔**即可退回纯静音 |

**裁决依据（推导）**：本作每步 60 s（房主设定 5~120 s），「对方回合」约 20 s 玩家完全无事做（量测自 `battle.js` 注释）；
这段空窗是真实的设计问题，而游戏本就 rAF 常驻重绘，多 2~3 个 oscillator 的 CPU 成本可忽略（推导）；
零音频文件、零包体增长（当前 449K / 上限 4MB，量测）。**因此做，但压到 −30 dB 的可关氛围，不做旋律。**

**风险控制（不是硬撑）**：① 音量压到 −30 dB，比最轻音效还低一个数量级（§5.4）；② 可关且持久化；
③ 保留 `AMB_ENABLE` 单一开关——真机试听若确认弊大于利，**改这一个布尔即可完全关闭氛围，不动任何事件代码**
（推导：把试错成本压到最低，而不是赌它会好听）。§9 第 5 条验收判据专门验这一点。

### 5.2 `amb.lobby`（大厅）

- 低频铺底：`sine` 110 Hz (A2) + 165 Hz (E3，纯五度，算得) 同时起，经 lowpass 800 Hz（推导：只留暖厚基频）。
- 极慢起伏：对铺底 gain 施加 0.1 Hz 正弦 LFO，幅度 ±20%（推导：10 s 一个呼吸，慢到不被察觉为「节奏」）。
- 随机点缀：每 4~9 s（推导：随机间隔避免可预测的机械感）播一枚短 `sine` 音，音高从五声音阶
  `[440, 523, 659, 784, 880]` Hz 随机取（算得：A4-C5-E5-G5-A5），A=30, D=400，gain 0.3（相对 amb bus）。
- 无鼓点、无旋律线（推导：大厅停留时间短，旋律来不及展开反成噪音）。

### 5.3 `amb.battle`（战斗）

- 铺底：同结构，`sine` 98 Hz (G2) + 147 Hz (D3，纯五度，算得)，lowpass 700 Hz（推导：比大厅略低、略暗 = 紧张）。
- 慢脉冲：每 2 s 一次极轻的 `sine` 70 Hz、A=20, D=180、gain 0.25（相对 amb bus）——只给心跳般的暗示，不做鼓（推导：回合制不需要推进感）。
- 随机点缀：每 6~12 s 一次 highpass 3000 Hz 的白噪 40 ms，gain 0.12（相对 amb bus），像远处雷达的沙沙（推导：呼应 abyss 视觉）。此点缀随皮肤 `LP_SCALE` 略调亮度。
- 同一套合成器，无新波形、无新节点类型（推导：工程成本可控）。

### 5.4 循环与混音

- **循环方式**：铺底 oscillator 在解锁后持续运行（振荡器无「loop」概念，常开即是循环）；
  点缀由游戏 rAF 主循环用 `nextAmbientAt` 时间戳调度（推导：不用 setInterval，避免与游戏暂停 / 后台脱节）。
- **转场**：大厅↔战斗用 1.5 s gain 交叉淡入淡出（推导：对持续 drone 突然 ramp 会「啪」一声；
  1.5 s 够长，且比转场动画本身还短，不拖节奏）。
- **音量**：`bus.amb = 0.03`（−30.5 dB，暂定，真机听感验证）——必须低于最轻音效 `sfx.tick`（0.22）一个数量级（推导）。
- **duck**：见 §4.2。静音时 suspend amb（§6），不是只把 gain 置 0（省节点运行）。

## 6. 静音策略

| 项 | 裁决 | 出处 |
|---|---|---|
| 默认状态 | **开**（音效 + 氛围） | 推导：静音开局会让玩家以为游戏坏了；音效是本作主要反馈通道（81 格读数的听觉补充） |
| 静音键形态 | **大厅 Canvas 自绘按钮 + zone**（项目铁律：禁止原生覆盖按钮）；位置在 `lobby.js` **皮肤按钮左侧同一行** | 量测：程基岩 T17 + 项目铁律 |
| 图标语义 | 中文「**音 / 静**」二字，或几何「喇叭 + 斜杠」；**禁止 emoji**（字体渲染不一致） | 量测：程基岩建议，采纳；状态可见、跨平台一致 |
| 状态文案 | 常驻文字「音效 开 / 关」随状态切换，不只靠图标 | 推导：可访问性，状态必须可读 |
| 状态提示 | 切换时播 `sfx.ui.tap`（开→关前最后一声确认；关→开时解锁后第一声） | 推导：给即时听觉反馈，证明开关生效 |
| 持久化 | `wx.setStorageSync` 键 `audio.muted`（bool），沿用 `skin.js` / `profile.js` 范式 | 量测自代码 |
| 首次解锁 | `AudioContext` 延迟创建；首个用户手势（大厅任意 tap）`resume()` + 播 `sfx.ui.tap` | 微信小游戏音频策略 + 推导 |
| 静音实现 | `ctx.suspend()`（同时停 amb 与后续 sfx），非仅 gain=0 | 推导：省电、避免后台残留 |
| 后台 | `visibilitychange:hidden` → suspend；回前台若未静音 → resume | 推导：与 `core/fx.js` 后台 dt 处理同源 |

## 7. 可访问性与边界

### 7.1 频率上限（防刺耳）

- `MASTER_LP = 7000 Hz`（lowpass, Q=0.707，推导）：手机扬声器在 ~8 kHz 以上本就滚降，7 kHz 截止砍掉数码毛刺与 3–6 kHz 高频顶端，不影响任何事件的语义信息。
- **任何事件不得有 >5 kHz 的持续纯音**（推导：耳道共振在 2–4 kHz，最易疲劳）。
- 2–4 kHz 内容只允许短瞬态（<60 ms）且系数 ≤0.35（推导：`sfx.hit` 的 1340 Hz 泛音、`sfx.tick.urgent` 的双音已按此约束设计）。
- `sfx.deploy.invalid` 恒 <1 kHz（推导：错误音绝不能是尖利蜂鸣）。

### 7.2 连续开火不叠成噪音

- 同发数 `VOICES_MAX = 6` + **同 ID** 去抖 `SAME_ID_DEBOUNCE_MS = 40`（推导：40 ms 低于人耳可分辨的两次点击间隔，过滤误触连点）。
- **跨事件**去抖 `TAP_FIRE_DEDUP_MS = 60`（量测：程基岩 T17 要在实现里做）——同一次点击里 `sfx.ui.tap` 与
  `sfx.fire` 会叠一记，工程择一或错开；因此所有短音（尤其 `sfx.ui.tap`）的识别特征放在 10–30 ms 主体，
  **不依赖极短初始瞬态**（§2.1）。
- 回合制本身限制了一回合只能开一炮（量测自玩法）；叠加风险主要来自结果音 + tick + amb 同帧，已由优先级与 duck 处理。
- 同一炮结果去重（§4.2）防 `hit`/`kill` 连播。

### 7.3 T-08 不泄密（音频层硬约束）

> 铁律 T-08：不揭示对方飞机形状。音频只能按「我打出的炮的结果」响。

1. **结果音唯一数据源**：`sfx.miss / sfx.hit / sfx.kill` 的触发参数**只允许**取服务端对我方这一炮返回的结果
   `marks[我][key] ∈ {miss, hit, kill}`（`battle.js` 已用 `resultOf(k)` 解析，量测自代码）。
2. **不接对方棋盘**：音频模块不得接收 `incoming[我]`、对方 `marks`、对方飞机布局或任何格子归属数据——
   连「读一下」都不做，从接口层面杜绝（推导：不给泄密留路径）。
3. **机翼/机身/机尾同音**：三者服务端结果都是 `hit` → 同一种 `sfx.hit`；不做任何「打中哪个部位」的音色/音高变体（推导：否则等于泄露命中部位）。
4. **对方打我时**：**不播结果音**。最多播一枚中性 `sfx.fire`（系数 ×0.5，恒定不变）表示「有炮打来」——
   它在所有情况下完全相同，不携带结果信息（推导：我方棋盘本来就被标记、无秘密可言，但仍严格遵守「结果音只认我打出的炮」）。
5. **不做声像定位**：所有音效 mono 居中，禁止按列 / 方位 pan（推导：pan 是额外信息通道；且手机双扬声器布局下 pan 反而听不准）。
6. **无变体随机化泄密**：噪声 offset 随机只为去机械感（§1.1），与任何棋盘状态无关；禁止「按命中数/剩余架数改变音色」这类设计（推导：那是把全局状态编码进声音）。

### 7.4 平台风险（真机待验）

- **iOS 物理静音键**：iOS 上拨到静音后 Web Audio 可能无声，官方无明确定论（量测：程基岩 T17 风险清单）。
  **不做规避设计**——静音键是系统级用户意图，游戏无权覆盖；本规格做的是「用户主动关 / 开」的游戏内开关（§6），
  两者互不冲突。真机验收时（§9）记录该现象，若确认无声则在 PRD 层提示用户，不在代码里 hack。
- **首次解锁失败**：若首个手势被系统吞掉导致 `ctx` 仍 suspended，下一次 tap 必须再试 `resume()`（推导：幂等重试，无副作用）。

## 9. 验收清单（真机听感验证用）

所有「暂定」值需在真机（微信小游戏 · 至少一台 Android + 一台 iOS）逐项听感验证；以下为判据：

- [ ] 16 个事件 ID 全部可独立触发，无一个静默、无一个串音。
- [ ] **事件驱动验证**：盯 `render` 无一声音重复——静止 5 s 应完全无声（除 amb）；点一次开火只响一记 `fire` +
      结果回来只响一记三态音；倒计时 5→1 恰好五记 tick。
- [ ] `miss` / `hit` / `kill` 三者闭眼可辨，且**不会**因为对方飞机不同而变化（T-08）。
- [ ] `kill` 明显盖过 `hit`；连点开火无爆音、无糊成一片；tap 与 fire 撞车时无「叠一记」。
- [ ] `sfx.tick` 在 >5 s 时「存在但不烦」，≤5 s 时 `tick.urgent` 明显升级。
- [ ] 氛围在战斗中「几乎注意不到，关掉后才发现少了一层」；P0 触发时 ducks 自然无泵感；
      **翻 `AMB_ENABLE=false` 后完全退回纯静音且不报任何事件错误**（§5.1 的退出路径）。
- [ ] 换肤后只有音色明暗 / 尾长变化，音高与事件语义完全一致。
- [ ] 静音 / 解锁 / 后台挂起恢复正常；首次点击有声确认；静音键为 Canvas 自绘、位置在皮肤按钮左侧。
- [ ] 所有事件无 >5 kHz 持续纯音；最大音量下 limiter 无削波失真。
- [ ] **iOS 物理静音键**行为记录下来（§7.4）；若确认无声，反馈到 PRD 层提示用户，不改代码。
