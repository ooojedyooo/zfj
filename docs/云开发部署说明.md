# 炸飞机 · 云开发部署说明

本文档说明如何把「炸飞机」的云端部分跑起来。全程在**微信开发者工具**里操作，不需要购买服务器。

---

## 零、先确认账号类型：这是「小游戏」，不是「小程序」

微信按**注册时的服务类目**区分小程序与小游戏，**注册后不可逆**。本项目账号的服务类目是
**游戏**，即**小游戏账号**，因此：

| | 微信小程序 | 微信小游戏 |
|---|---|---|
| 入口 | `app.json` + `app.js` | `game.json` + `game.js` |
| 界面 | WXML + WXSS，多页面 | 无 WXML/WXSS/DOM，**Canvas 手绘** |
| 本项目 | `miniprogram/`（逻辑真源 + 参照实现） | **`minigame/`（上架用的主线）** |

**症状对照**：如果在小程序工程里填了小游戏 AppID，编译会报

```
app.json 文件内容错误: miniprogram/game.json: 未找到 或者文件读取失败
```

原因是**开发者工具按 AppID 的账号类型决定编译模式**，`project.config.json` 里的
`compileType` 改不动它。此时只能二选一：

- 换成**小程序账号**的 AppID，用 `miniprogram/` 那套工程；
- 或者保留小游戏 AppID，用 `minigame/` 那套工程（本项目现状）。

`project.config.json` 已按小游戏配置：

```json
{
  "miniprogramRoot": "minigame/",
  "cloudfunctionRoot": "cloudfunctions/",
  "compileType": "game"
}
```

> 改完 `appid` 后**必须移除项目再重新导入**，工具才会重新拉取账号类型。

## 一、前置准备

### 1. 拿到小游戏 AppID

1. 访问 [微信公众平台](https://mp.weixin.qq.com/) ，用已注册的小游戏账号登录
2. 在「开发 → 开发管理 → 开发设置」里复制 **AppID**
3. 填进项目根目录的 `project.config.json`：

```json
{
  "appid": "wx你的AppID"
}
```

> 小游戏必须用真实 AppID —— 游客模式无法判定账号类型，云开发也要求真实 AppID。

### 2. 开通云开发并创建环境
1. 用微信开发者工具打开本项目（认 `project.config.json` 所在目录）
2. 点击工具栏的 **「云开发」** 按钮，按引导开通
3. 创建一个环境（例如命名为 `zfj-prod`）
4. 在云开发控制台「设置 → 环境」里复制 **环境 ID**（形如 `zfj-prod-1gxxxxxx`）

### 3. 打开云开关、填写环境 ID、然后同步
打开 `miniprogram/config/cloud.js`：

```js
module.exports = {
  ENV_ID: 'zfj-prod-1gxxxxxx',   // ← 填入你的环境 ID
  USE_CLOUD: true,               // ← 默认是 false（离线试玩），联机必须改成 true
  ...
}
```

**然后必须执行**（这是最容易漏的一步）：

```bash
node scripts/sync-shared.js
```

`miniprogram/` 是逻辑真源，小游戏端与云函数用的都是它的副本。
**每改一次 `miniprogram/{config,utils,services}`，都要重跑同步脚本**，
否则两端逻辑会漂移 —— 典型后果是云端拿到的表情白名单、机型配置和客户端不是同一份。

> `USE_CLOUD` 是整个项目唯一的「离线 / 联机」总开关，详见 [第七节](#七本地离线试玩无云环境时)。

## 二、创建数据库集合与权限

在云开发控制台 →「数据库」中，创建 **两个集合**，并按下表设置权限：

| 集合名 | 用途 | 权限设置 | 说明 |
|---|---|---|---|
| `rooms` | 房间与对局**公开视图** | **所有用户可读** | 客户端需要 `watch` 它来实时同步战况 |
| `games` | 双方**飞机布阵**（敏感） | **所有用户不可读写** | 只有云函数（管理端）能访问 |

> ⚠️ **这一步是安全的关键**。`games` 集合必须设为"所有用户不可读写"，
> 否则理论上客户端可以直接查库，看到对方飞机位置——T-08（不泄露飞机形状）就失效了。
> 注意：小游戏端**同样不做任何判定**，不能因为「反正是 canvas，用户看不到」就放松权限。

**创建步骤**：数据库 → 添加集合 → 输入集合名 → 创建 → 点击集合右侧「权限设置」→ 选择对应权限。

### 4. 云函数里的共享代码也要更新

`cloudfunctions/{room,game}/shared/` 是 `sync-shared.js` 同步出来的副本。
同一段逻辑如果只改了小程序端、没重跑同步脚本、也没重传云函数，就会出现
**客户端判定与服务端判定不一致**。所以部署流程固定为：

```
改 miniprogram/{config,utils,services}
  → node scripts/sync-shared.js
  → node scripts/test-core.js && node scripts/test-offline-flow.js
  → 在开发者工具里重新上传 room / game 云函数
```

## 三、上传云函数

本项目包含三个云函数：

| 云函数 | 作用 |
|---|---|
| `room` | 创建房间 / 加入 / 随机匹配 / 退出 |
| `game` | 布阵校验 / 开火判定 / 快捷表情 / 投降 / 回合超时 |
| `cleanup` | 定时清理超时房间与过期对局 |

> ⚠️ `game` 与 `room` 都依赖 `shared/` 目录下的共用逻辑（来自 `miniprogram/{config,utils}` 的副本）。
> 每次改动 `miniprogram/config`、`miniprogram/utils` 或 `miniprogram/services` 后，
> 必须先跑 `node scripts/sync-shared.js`，再重新上传这两个云函数，
> 否则会出现「本地能布阵、云端说非法」这类不一致。

**上传步骤**（对每个云函数重复）：
1. 在开发者工具左侧文件树展开 `cloudfunctions/`
2. **右键** `room` 文件夹 → 选择 **「上传并部署：云端安装依赖」**
3. 等待右下角提示上传成功
4. 同样操作 `game`、`cleanup`

> 选「云端安装依赖」是因为云函数依赖 `wx-server-sdk`，由云端自动 `npm install`，本地无需安装。
> 如果改了 `shared/` 之后上传，右键菜单建议选「上传并部署：所有文件」，
> 避免增量上传漏掉 `shared/` 里的新文件。

### 配置定时触发器（清理任务）
上传 `cleanup` 后：
1. 云开发控制台 →「云函数」→ 找到 `cleanup` → 点击进入详情
2. 切到 **「触发器」** 标签页 → 若未自动创建，手动新增一个 **定时触发器**
3. 触发周期填：`0 */5 * * * * *`（每 5 分钟一次）
4. 保存

> `cloudfunctions/cleanup/config.json` 里已写好该触发器配置，部分版本的开发者工具会在上传时自动创建。

## 五、数据模型说明

### `rooms`（公开视图，客户端可读）

```js
{
  _id: '房间ID',
  roomNo: '123456',            // 6 位房间号
  isPublic: true,              // 是否公开房
  planeCount: 1,               // 本局飞机数量（1~3）
  status: 'waiting',           // waiting | deploy | battle | finished
  players: [
    { openid: 'xxx', ready: false, joinedAt: 1696000000000 }
  ],
  battle: {                    // 对局公开视图（对局开始后才有）
    turn: 'openid',            // 当前轮到谁
    seq: 3,                    // 出手序号
    lastMove: { row, col, result, by, at },
    marks:    { 'openidA': { '3,4': 'hit' } },   // A 轰炸对手的记录
    incoming: { 'openidA': { '5,5': 'hit' } },   // A 自己棋盘被炸的记录
    stats:    { 'openidA': { kill: 1, lost: 0, shots: 5 } },
    finished: false,
    winner: '',
    endType: '',               // all_destroyed | surrender | timeout
    turnDeadline: 1696000030000,
    emote: {                   // 最新一条快捷表情（局内社交）
      by: 'openidA',           // 谁发的
      emoji: '👍',
      at: 1696000020000,
      seq: 7                   // 与 battle.seq 共用，客户端据此去重
    }
  },
  createdAt: 1696000000000,
  updatedAt: 1696000000000,
  expireAt: 1696000300000      // 房间超时时间
}
```

### `games`（敏感，仅云函数可读写）

```js
{
  _id: '房间ID',
  deploys: {
    'openidA': [ { planeId: 'standard', anchorRow: 3, anchorCol: 3, rotation: 0 } ],
    'openidB': [ ... ]
  },
  killed: { 'openidA': [0], 'openidB': [] },   // 各自被击毁的飞机序号
  ready:  { 'openidA': true, 'openidB': false }
}
```

> 玩家飞机位置只存在于这里，客户端**永远读取不到**。

## 六、安全设计（为什么这样分层）

| 风险 | 防护 |
|---|---|
| 客户端伪造布阵（放不合法的位置） | `game.deploy` 在服务端用**同一份** `utils/plane.js` 重新校验 |
| 客户端直接读对方布阵 | 布阵存在 `games` 集合，权限设为"所有用户不可读写" |
| 客户端伪造命中结果 | 判定只在 `game.fire` 里做，客户端只收结果 |
| 击毁后泄露飞机形状 | `fire` 只返回 `result`，**绝不返回**飞机格位与朝向（T-08） |
| 绕过回合限制连开炮 | `fire` 先校验 `battle.turn === openid` |
| 重复报点 | 界面层置灰 + `fire` 里再判一次 `marks` 是否已有该坐标 |
| 回合超时 | `tick` 按服务端时间戳判定，双方均可触发但结果幂等 |
| 表情内容注入 | `emote` 用 `config/social.js` 的**白名单**校验，且必须是对局中的本方玩家 |

## 七、本地离线试玩（无云环境时）

**这是项目的默认状态**（`USE_CLOUD: false`），不需要任何云环境，
用微信开发者工具导入本目录、点「编译」就能把一局完整打完：

```
创建房间 → 约 2.5 秒后「对手」自动加入 → 布阵 → 随机先手 → 轮流开火 → 结算
```

此时 `shared/services/cloudApi.js` 会把所有请求分派给 `shared/services/offlineGame.js`：

| 环节 | 离线实现 |
|---|---|
| 对手 | 本地 AI：优先追打已命中格的相邻格，否则随机打未炸过的格 |
| `watchRoom` | 本地事件广播（立即推一次当前状态，之后状态变更时推送） |
| 房间号 / 先手随机 / 严格交替 / 判定 | 与云端同源逻辑（`utils/plane.js`、`utils/judge.js`） |

> 场景 / 页面代码在两种模式下**完全一样**，因此离线跑通就等于联机跑通（除对手不是真人）。

**想调整 AI 的「演技」**（等待时长）：

```js
// 小程序端：在控制台执行
require('services/offlineGame').setDelays({ opponentJoin: 1000, foeAction: 600 })
// 小游戏端路径为 './js/shared/services/offlineGame'
```

**离线引擎的自动化回归**：

```bash
node scripts/test-core.js           # 22 项，纯函数（形状 / 旋转 / 判定 / 随机布阵）
node scripts/test-offline-flow.js   # 45 项，建房 → 布阵 → 开火 → 结算全链路
node scripts/test-minigame.js       # 58 项，小游戏端渲染 + 触摸分发端到端
```

## 九、常见问题

**Q：编译报错「app.json 文件内容错误: miniprogram/game.json: 未找到」**

**这不是代码问题，是 AppID 类型问题。**（本项目已通过重写为小游戏工程解决，保留此条以备考。）

开发者工具按哪种模式编译，是由 **AppID 的账号类型**决定的，而不是 `project.config.json` 里的
`compileType` —— **本地把 `compileType` 改成 `miniprogram` 无效**，工具会按 AppID 从服务端拉取的结果覆盖它。

若 `appid` 填的是**小游戏（game）账号**，工具就去找小游戏入口 `game.json`
（路径 = `miniprogramRoot` + `game.json`）。反过来，把**小游戏 AppID 填进小程序工程**，
而工程只有 `app.json`，就会报上面这个错。

**判定账号类型**：打开[微信公众平台](https://mp.weixin.qq.com/) → 设置 → 基本设置 → 看「服务类目」。
服务类目是**游戏** = 小游戏账号（**注册后不可逆**）。

**两种解法**：

| 场景 | 做法 |
|---|---|
| 账号是小游戏（本项目） | 保留小游戏 AppID，用 `minigame/` 工程，`compileType: "game"` |
| 账号是小程序 | 用小程序 AppID，改用 `miniprogram/` 那套工程（把 `miniprogramRoot` 改回 `miniprogram/`、`compileType` 改回 `miniprogram`） |

> ⚠️ 改完 `appid` 之后，**必须移除项目再重新添加**。直接在原窗口改配置，
> 工具仍会按缓存的旧类型编译，看起来像是「改了没用」。
> 若仍异常，再执行「工具 → 清除缓存 → 全部清除」。

---

**Q：小游戏端改了玩法逻辑，但游戏里没生效**

小游戏端读的是 `minigame/js/shared/` 下的副本，不是 `miniprogram/`。改完真源要跑：

```bash
node scripts/sync-shared.js
```

**Q：小游戏端界面点击没反应 / 点错位置**

排查顺序：① 该元素有没有在 `layout()` 里注册 `this.zone(...)`；
② 是否被上层 zone 覆盖（后注册者优先命中，可用 `disabled: true` 显式屏蔽）；
③ `layout()` 是否在进入场景或状态变化时被重新调用（zones 是按当时的布局算出来的）。

**Q：小游戏端渲染错位、字太小/太大**

小游戏只有 canvas，尺寸全按 `layout.u()` 把 750 设计稿单位换算成 px。
不要写死像素值，一律走 `u(...)`；`layout` 已处理 DPR 缩放与安全区。

---

**Q：提示「当前基础库不支持云开发」**
在开发者工具「详情 → 本地设置」里把调试基础库调到 **2.2.3 及以上**。

**Q：调用云函数报 `-501000` / 环境不存在**
检查 `ENV_ID` 是否与控制台一致（小游戏端看 `minigame/js/shared/config/cloud.js`，
它是从 `miniprogram/config/cloud.js` 同步来的）；若账号下只有一个环境，也可留空使用默认环境。

**Q：业务域名 / 服务器域名没配置怎么办**
云开发不需要配置服务器域名，`wx.cloud` 走的是内部通道。

**Q：两个人只能匹配到自己**
匹配池是全局的，确保两台设备登录的是**不同的微信账号**。

**Q：修改了 `miniprogram/utils` 或 `miniprogram/config`，云端结果对不上**
云函数用的是 `cloudfunctions/*/shared/` 下的副本，小游戏端用的是 `minigame/js/shared/` 下的副本，
两处都需要重新同步：

```bash
node scripts/sync-shared.js
```

然后重新「上传并部署」`room` 和 `game` 两个云函数。

**Q：分享出去的房间卡片，好友点开进不去**
房间默认 5 分钟未开局会自动解散（T-10），超时后房间号即失效。
另外密码房请确认卡片里带上了 `pwd` 参数——房间页的转发会自动拼上。

**Q：好友点开分享卡片后，房间号没自动填上**
小程序端的分享路径形如 `pages/room/room?mode=join&roomNo=123456`；
小游戏端没有 path，转发带的是 **`query` 串**（形如 `mode=join&roomNo=123456`），
由 `js/core/share.js` 的 `parseQuery()` 解析、`game.js` 的 `wx.onShow` 接住并跳到房间场景。
如果房间号为空，说明分享时房间还没创建成功（房间页会在创建完成后才带上房间号）。
