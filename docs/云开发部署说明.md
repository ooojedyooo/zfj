# 炸飞机 · 云开发部署说明

本文档说明如何把「炸飞机」的云端部分跑起来。全程在**微信开发者工具**里操作，不需要购买服务器。

---

## 一、前置准备

### 1. 注册小程序并拿到 AppID
1. 访问 [微信公众平台](https://mp.weixin.qq.com/) 注册一个小程序账号
2. 在「开发 → 开发管理 → 开发设置」里复制 **AppID**
3. 把它填进项目根目录的 `project.config.json`：

```json
{
  "appid": "wx你的AppID"
}
```

> 没有 AppID 也能以「游客模式 / 测试号」预览界面，但**云开发必须用真实 AppID**。

### 2. 开通云开发并创建环境
1. 用微信开发者工具打开本项目（认 `project.config.json` 所在目录）
2. 点击工具栏的 **「云开发」** 按钮，按引导开通
3. 创建一个环境（例如命名为 `zfj-prod`）
4. 在云开发控制台「设置 → 环境」里复制 **环境 ID**（形如 `zfj-prod-1gxxxxxx`）

### 3. 填写环境 ID
打开 `miniprogram/config/cloud.js`，填入环境 ID：

```js
module.exports = {
  ENV_ID: 'zfj-prod-1gxxxxxx',   // ← 这里
  USE_CLOUD: true,
  ...
}
```

## 二、创建数据库集合与权限

在云开发控制台 →「数据库」中，创建 **两个集合**，并按下表设置权限：

| 集合名 | 用途 | 权限设置 | 说明 |
|---|---|---|---|
| `rooms` | 房间与对局**公开视图** | **所有用户可读** | 客户端需要 `watch` 它来实时同步战况 |
| `games` | 双方**飞机布阵**（敏感） | **所有用户不可读写** | 只有云函数（管理端）能访问 |

> ⚠️ **这一步是安全的关键**。`games` 集合必须设为"所有用户不可读写"，
> 否则理论上客户端可以直接查库，看到对方飞机位置——T-08（不泄露飞机形状）就失效了。

**创建步骤**：数据库 → 添加集合 → 输入集合名 → 创建 → 点击集合右侧「权限设置」→ 选择对应权限。

---

## 三、上传云函数

本项目包含三个云函数：

| 云函数 | 作用 |
|---|---|
| `room` | 创建房间 / 加入 / 随机匹配 / 退出 |
| `game` | 布阵校验 / 开火判定 / 投降 / 回合超时 |
| `cleanup` | 定时清理超时房间与过期对局 |

**上传步骤**（对每个云函数重复）：
1. 在开发者工具左侧文件树展开 `cloudfunctions/`
2. **右键** `room` 文件夹 → 选择 **「上传并部署：云端安装依赖」**
3. 等待右下角提示上传成功
4. 同样操作 `game`、`cleanup`

> 选「云端安装依赖」是因为云函数依赖 `wx-server-sdk`，由云端自动 `npm install`，本地无需安装。

### 配置定时触发器（清理任务）
上传 `cleanup` 后：
1. 云开发控制台 →「云函数」→ 找到 `cleanup` → 点击进入详情
2. 切到 **「触发器」** 标签页 → 若未自动创建，手动新增一个 **定时触发器**
3. 触发周期填：`0 */5 * * * * *`（每 5 分钟一次）
4. 保存

> `cloudfunctions/cleanup/config.json` 里已写好该触发器配置，部分版本的开发者工具会在上传时自动创建。

## 四、验证部署

1. 在开发者工具中点击「编译」
2. 首页点「随机匹配」
3. 会提示「等待对手加入」并显示 6 位房间号

**单人自测技巧**：用两台设备（或「真机调试」+ 工具模拟器）分别进入，
一台「创建房间」，另一台用房间号「加入房间」，即可完成一局真实对战。

也可以直接开两个开发者工具窗口，用「多账号调试」功能模拟两个用户。

## 五、数据模型说明

### `rooms`（公开视图，客户端可读）

```js
{
  _id: '房间ID',
  roomNo: '123456',            // 6 位房间号
  isPublic: true,              // 是否公开房
  planeCount: 1,               // 本局飞机数量（1~3）
  status: 'waiting',           // waiting | deploy | battle | finished
  players: [
    { openid: 'xxx', ready: false, joinedAt: 1696000000000 }
  ],
  battle: {                    // 对局公开视图（对局开始后才有）
    turn: 'openid',            // 当前轮到谁
    seq: 3,                    // 出手序号
    lastMove: { row, col, result, by, at },
    marks:    { 'openidA': { '3,4': 'hit' } },   // A 轰炸对手的记录
    incoming: { 'openidA': { '5,5': 'hit' } },   // A 自己棋盘被炸的记录
    stats:    { 'openidA': { kill: 1, lost: 0, shots: 5 } },
    finished: false,
    winner: '',
    endType: '',               // all_destroyed | surrender | timeout
    turnDeadline: 1696000030000
  },
  createdAt: 1696000000000,
  updatedAt: 1696000000000,
  expireAt: 1696000300000      // 房间超时时间
}
```

### `games`（敏感，仅云函数可读写）

```js
{
  _id: '房间ID',
  deploys: {
    'openidA': [ { planeId: 'standard', anchorRow: 3, anchorCol: 3, rotation: 0 } ],
    'openidB': [ ... ]
  },
  killed: { 'openidA': [0], 'openidB': [] },   // 各自被击毁的飞机序号
  ready:  { 'openidA': true, 'openidB': false }
}
```

> 玩家飞机位置只存在于这里，客户端**永远读取不到**。

## 六、安全设计（为什么这样分层）

| 风险 | 防护 |
|---|---|
| 客户端伪造布阵（放不合法的位置） | `game.deploy` 在服务端用**同一份** `utils/plane.js` 重新校验 |
| 客户端直接读对方布阵 | 布阵存在 `games` 集合，权限设为"所有用户不可读写" |
| 客户端伪造命中结果 | 判定只在 `game.fire` 里做，客户端只收结果 |
| 击毁后泄露飞机形状 | `fire` 只返回 `result`，**绝不返回**飞机格位与朝向（T-08） |
| 绕过回合限制连开炮 | `fire` 先校验 `battle.turn === openid` |
| 重复报点 | 界面层置灰 + `fire` 里再判一次 `marks` 是否已有该坐标 |
| 回合超时 | `tick` 按服务端时间戳判定，双方均可触发但结果幂等 |

## 七、本地离线调试（无云环境时）

如果暂时不想开通云开发，可以把开关关掉，用本地模拟引擎跑通界面：

```js
// miniprogram/config/cloud.js
USE_CLOUD: false
```

此时对手由 `services/localGame.js` 在本地模拟，除了不能真人对战，其余流程（布阵 / 报点 / 判定 / 结算）完全一致。

## 八、常见问题

**Q：提示「当前基础库不支持云开发」**
在开发者工具「详情 → 本地设置」里把调试基础库调到 **2.2.3 及以上**。

**Q：调用云函数报 `-501000` / 环境不存在**
检查 `miniprogram/config/cloud.js` 的 `ENV_ID` 是否与控制台一致；若账号下只有一个环境，也可留空使用默认环境。

**Q：业务域名 / 服务器域名没配置怎么办**
云开发不需要配置服务器域名，`wx.cloud` 走的是内部通道。

**Q：两个人只能匹配到自己**
匹配池是全局的，确保两台设备登录的是**不同的微信账号**。

**Q：修改了 `miniprogram/utils` 或 `miniprogram/config`，云端结果对不上**
云函数用的是 `cloudfunctions/*/shared/` 下的副本，需要重新同步并上传：

```bash
node scripts/sync-shared.js
```

然后重新「上传并部署」`room` 和 `game` 两个云函数。
